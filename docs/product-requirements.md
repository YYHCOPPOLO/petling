# AgentPet 产品需求

更新日期：2026-10-21。本文记录本轮需求讨论确认的产品目标；功能实现状态以 [重构评估](agent-refactor-assessment.md)、[基础版本重构](basic-refactor.md) 和 [验证记录](verification.md) 为准。

## 产品定位与已确认范围

AgentPet 是一个有持续性格和记忆的桌面伙伴，能够自己完成任务，也能组织其他 Agent 一起工作。日常使用以陪伴、聊天和互动为中心，任务能力融入同一套体验。

已确认的方向：

- 宠物具有自己的 Agent 能力，能够理解目标、选择工具、执行步骤、检查结果和处理失败。
- 同时支持集成外部 Agent 和接续它们的任务、会话与可交接的记忆；外部 Agent 也能调用宠物能力。
- 笔记与提醒、文件查找整理、项目理解与方案讨论、桌面应用操作，全部属于必须实现的本体能力。
- 性格、共同经历、用户偏好和任务记录持续保留，切换模型或外部后端不改变宠物身份。
- 真实阅读属于文件与知识技能。互动、自身 Agent 和外部协作共同构成开发主线。
- 保留养成、动画、背包、装扮、学习打工等现有基础能力；复杂小游戏继续后置。
- 在完整功能基础上实现应用轻量化、运行时低占用和高性能；按需加载、受控并发和资源回收贯穿所有能力与开发阶段。

下表中的全部能力均进入完整目标。分期用于安排依赖和交付顺序，不把尚未进入早期里程碑的能力移出需求。

## 能力清单与验收目标

| 编号 | 能力 | 必须支持的行为 | 完成标准 |
| --- | --- | --- | --- |
| R01 | 陪伴互动 | 聊天、点击与抚摸、动作和情绪反馈；持续的名字、性格、称呼与共同经历；主动搭话频率可调 | 重启和切换后端后身份与已保存的偏好连续；交互有可见反馈；聊天、任务进度、提醒和建议的通知策略可分别设置 |
| R02 | 自身 Agent | 理解目标、拆分步骤、调用工具、检查产物、处理失败；必要时追问；支持取消和恢复 | 无需委派外部 Agent，也能完成已接入的本体技能；任务结果依据工具和产物，支持结构化错误与明确的恢复边界 |
| R03 | 笔记与提醒 | 从对话创建、查询、修改笔记、待办和提醒；完成待办、取消提醒、设置重复提醒 | 内容和时间规则持久化；修改和取消及时生效；重复投递、重启、休眠及错过触发时间都有明确行为，不重复创建或通知 |
| R04 | 文件与阅读 | 在指定范围内搜索、读取、分类、整理文件；读取 TXT、Markdown、文本 PDF；总结、引用、后续问答 | 整理结果与实际文件一致，冲突和失败可解释；摘要能定位到对应版本的原文；重启后仍可检索；未处理内容不标为已读 |
| R05 | 项目伙伴 | 理解项目结构和文档，讨论需求、分析问题、形成方案、记录决定，将明确任务交给合适的 Agent | 能说明方案依据，保存讨论决定与待办，并把目标、约束、文件范围和验收要求传给执行者；执行结果关联回原项目与任务 |
| R06 | 桌面应用操作 | 打开和定位应用、操作控件、填写内容、读取结果，完成跨步骤工作流程 | 按平台、应用和流程清单验收；能确认目标应用和实际结果，处理焦点变化、页面变化、失败与中断；发出点击或输入不等于任务成功 |
| R07 | 外部 Agent 集成 | 委派任务、接收进度、等待输入、取得产物；外部 Agent 查询宠物、调用工具、检索知识和管理任务 | 内外部入口共享能力与任务状态；后端能力可发现；取消、异常、会话归属和进程清理可验证，扩展后端不需要重写业务技能 |
| R08 | 会话与任务接续 | 在支持的后端继续指定原会话；在宠物与不同 Agent 之间交接目标、决定、进度、产物和待办 | 能找到准确的原任务及会话，说明已完成和未完成部分；更换执行者后工作可继续，已经提交的副作用不重复执行 |
| R09 | 长期记忆 | 分别管理个人偏好、共同经历、项目知识和任务记录；支持查看、纠正、遗忘与备份 | 用户能识别记忆来源并修改或删除；删除后不再召回；不会把全部临时任务上下文自动变成个人偏好；跨重启、跨后端保留应用持有的数据 |

R06 的兼容范围通过应用与操作清单逐步扩展，不以“任意软件都能操作”作为未经验证的能力说明。R08 的原生会话恢复依赖具体后端支持，跨后端接续以工作上下文交接验收。

## 连贯的使用体验

代表性场景：用户说“看看这个项目，把我们讨论的改进记下来，交给代码 Agent，完成后在编辑器里打开结果，晚上提醒我检查”。

1. 宠物确定指定项目和本次目标，读取相关资料，与用户讨论；信息不足时只补问影响执行的内容。
2. 把已确认的决定保存成笔记与待办，关联项目和本次会话，用户可以纠正内容。
3. 创建可跟踪的任务，为外部 Agent 提供目标、约束、范围和验收要求；委派前后的任务保持关联。
4. 按真实执行事件显示进度。需要输入或授权时显示等待状态；用户可以查看、取消或继续任务。
5. 接收并检查结果、产物和未完成项，在受支持的编辑器中打开并定位对应文件，核对应用状态；再用宠物自己的语气反馈，明确哪些工作由外部 Agent 执行。
6. 按确定的日期、时间和时区建立提醒；关联需要检查的任务与结果，不凭“晚上”生成无法解释的任意时间。
7. 重启后用户说“昨天那件事继续”，宠物能定位原任务、说明停留位置，并恢复受支持的步骤；有多个候选时提供选择。

该场景贯穿 R01–R09。各技能也应能独立使用；用户只想聊天、记笔记或整理文件时，无需先建立复杂项目。

## 交互、性格与主动性

- 宠物身份由应用管理，包含名字、性格、表达偏好和共同经历。模型与执行后端是可替换的实现。
- 性格影响语气、动作和提醒方式。任务是否成功由真实执行结果决定；外部 Agent 的结果应准确归属。
- 气泡承载简短互动与提醒；展开面板承载长对话、附件、任务详情、笔记、知识来源和结果。
- 主动聊天、任务进度通知、定时提醒和主动建议分别控制，支持安静陪伴与任务完成通知的组合。
- 执行范围可按任务或工作目录持续授权，并可查看和撤销；在已授权范围内避免重复询问。主动建议的开关不自动扩大工具执行范围。
- 养成状态与 Agent 任务独立。隐藏宠物、关闭聊天面板、饥饿、死亡或暂停成长不应中断知识查询和工作任务；喂食、治疗等游戏操作继续遵守已有规则。

## 接续、记忆与数据归属

“集成”负责委派和双向工具调用。“接续”包含两种可分别验证的能力：

| 接续方式 | 交接内容 | 边界 |
| --- | --- | --- |
| 继续原会话 | 后端标识、明确的会话 ID、任务关联及后端支持的恢复状态 | 不使用“最近一次会话”猜测目标；不支持时说明限制并提供上下文交接或重新执行 |
| 交接工作上下文 | 目标、约束、关键决定、已完成步骤、产物与文件版本、待办、知识引用和待解决问题 | 适用于跨后端；不承诺厂商原生会话、内部状态或全部记忆格式可无损迁移 |

应用持有任务与结果的公共记录，包括任务及父子关联、来源、执行后端、会话标识、检查点、工具执行记录和产物。交接后已有执行记录仍可追溯，任务涉及的权限范围不会因更换执行者自动扩大。

长期数据分别管理：

- 个人偏好：用户希望宠物记住的称呼、习惯和偏好，支持确认、纠正和遗忘。
- 共同经历：需要长期保留的互动与共同决定，能够查看来源。
- 项目与文档知识：保存项目关联、文档版本、原文位置和引用。
- 会话与任务记录：保存工作上下文和执行事实，临时内容不自动全部沉淀为个人记忆。

删除文档或知识时同步处理摘要、索引及相关运行任务，防止迟到结果重新写回已删除内容。历史聊天副本是否删除、备份内容及宠物重生时的数据保留策略，应在相应操作中明确说明，具体策略列入实施前待定项。

## 执行与生命周期要求

UI、自身 Agent 和外部 Agent 共享能力注册、状态提交与任务管理。即时操作返回真实结果，耗时操作返回任务标识；能力具有输入输出约定、执行范围、错误和取消语义。

任务区分排队、执行、等待输入、等待授权、中断、成功、失败和取消。应用退出前保存检查点并停止本任务创建的进程；重新启动后按实际已完成的工作恢复。取消和重试不得导致迟到结果覆盖当前任务、重复扣物品、重复整理文件或重复创建提醒。

桌面应用操作、文件操作和外部任务使用可观察的结果验证；对无法确认是否已完成的副作用先核对实际状态，不盲目自动重试。游戏内学习打工继续按原规则结算，真实工作不能用离线时长推断完成。

笔记与提醒需要定义时区、重复规则、休眠唤醒和漏提醒策略。应用完全退出后是否仍由系统调度提醒或常驻执行尚未确认，发布提醒能力前必须明确并展示其运行边界。

本机凭据独立管理，备份和知识记录默认不含凭据。指定文件或项目中的文字属于任务材料，不自动构成新的工具调用授权。

## 轻量化、低占用与高性能

这三项是 R01–R09 的全局交付约束。全部能力继续保留，通过按需加载和按任务启用控制常驻成本；隐藏或省电时继续保障工作任务、提醒、状态保存和接续。

| 编号 | 全局要求 | 验收范围 |
| --- | --- | --- |
| N01 | 启动与分发轻量化 | 宠物尽快可交互，技能与依赖按需加载；安装包、安装后体积和新增依赖增量可追踪 |
| N02 | 低占用陪伴 | 可见待机、静态、隐藏和锁屏分别控制绘制与轮询，不保留无任务的重执行器 |
| N03 | 交互流畅 | 点击、拖拽、输入、打开面板和取消及时响应；本地反馈与模型响应耗时分别统计 |
| N04 | 工作负载有界 | 后台解析、检索、桌面观察和外部 Agent 使用受控并发与内存，繁忙时排队且不阻塞交互 |
| N05 | 长期运行稳定 | 增量读写、有限缓存和日志清理；反复使用与长期驻留不持续积累内存或临时文件 |
| N06 | 及时释放与恢复 | 面板关闭、任务结束/取消和退出释放对应资源；先保存工作记录，仍能接续任务 |
| N07 | 可测量与可回归 | 生产构建按固定场景测完整进程组，外部后端单列并报告总占用，各阶段同时检查功能和性能 |

具体初始预算、统计口径、基准场景和验收方法统一维护在 [轻量化与性能要求](performance-requirements.md)。数值属于待实测验证的工程目标；现有资源包瘦身记录不能替代 CPU、内存、GPU、启动和长期稳定性测试。

## 实施顺序

| 里程碑 | 交付范围 | 验收重点 |
| --- | --- | --- |
| M0：统一基础与协议 | 完成状态托管、工具入口、任务与记忆持久化、身份配置、执行事件和取消边界；完成参考后端探针与性能基线 | 一个权威写入口、请求去重、退出恢复、原会话标识和工具回调可验证；冻结测量场景与性能预算 |
| M1：核心互动与协作 | 聊天互动、自身 Agent 工具循环、任务面板、一个参考外部 Agent 的双向调用及受支持的任务接续 | 原生工具调用和外部委派都能完成真实任务；状态、结果、取消和重启连续，核心常驻与交互成本通过检查 |
| M2：全部本体技能 | 完整接入笔记提醒、文件阅读整理、项目协作和桌面应用操作 | R03–R06 分别通过测试，联合场景贯通；工作时 UI 响应、受控并发和资源回收符合预算 |
| M3：扩展与交接完善 | 更多后端、更多桌面应用、跨后端上下文交接、记忆管理和主动行为打磨 | 按兼容矩阵验证每个后端与应用，保持数据连续；记录多执行器组合的总资源占用 |
| M4：完整发布验证 | 数据迁移、异常恢复、资源与阅读质量、长期性能、分发体积、Windows/macOS 构建及运行验证 | 同时覆盖 R01–R09、N01–N07 和进程清理；现有基础玩法仍可离线使用 |

各阶段持续做功能与性能回归，M4 汇总完整发布验证。R01、R02、R07–R09 随里程碑逐步完善，不能把核心体验演示通过当作全部需求完成。原 2026-10-16 工期未包含本轮全部技能、桌面操作和完整性能约束，不能用于承诺新范围的剩余工期。

## 实施前需要补齐的参数

这些条目影响具体实现与验收范围，不改变上述能力都要实现的目标：

- 参考外部后端的具体实现、版本、登录方式、会话访问范围；DeepSeek harness 的确切仓库或程序。
- 首批桌面应用、版本、平台和操作流程；各平台的接入机制与兼容矩阵。
- 提醒的默认时区、重复与漏提醒规则，以及应用完全退出后的触发方案。
- 文件整理的默认目录范围、同名冲突与恢复策略；文件大小、页数、并发和模型用量上限。
- 主动互动的默认频率、安静时段、工作时的通知方式和持续授权粒度。
- 记忆写入策略、历史副本删除、备份恢复、宠物重生时的知识与任务保留方式。
- 性能参考设备、固定工作负载、各平台安装体积与 GPU 预算；M0 实测后记录冻结阈值及差距。

远程常驻服务、跨设备同步、OCR、语音以及复杂小游戏未在本轮确认纳入交付。原创熊猫资源沿用 [美术资源替换](assets.md) 的独立规划，不阻塞先用现有资源验证互动和任务流程。
