# M0 第一批：状态托管与可靠命令

2026-10-21 实施。对应产品需求 M0 的权威状态写入、命令契约和持久化去重；不是整个 M0 或完整 Agent 能力的交付。

## 已实现

- `PetHost` 在主进程持有唯一 `SaveRepository`。喂食、清洁、购买、诊断治疗、互动、课程、考试、领养、埋葬和托管全部通过 JSON 命令进入同一个宿主。
- 成长、疾病、自动喂养、限时物品、会员到期、游戏活动进度及奖励迁入主进程时钟。隐藏宠物或关闭面板不影响计时；暂停和死亡继续遵守旧游戏规则。真实工作任务尚未接入，也不使用这个游戏时钟。
- 时间、随机互动值、价格、库存和课程限制由宿主确定。托管的扣费与开通同次提交；医疗、死亡处理与派生等级同次提交。
- 渲染层只投影已经提交的养成状态；桌面位置、昵称和设置可以乐观显示并批量保存。旧 `save(patch)` 现在只接受这些偏好，拒绝余额、库存、课程、活动和成长等养成字段。
- `requestId`、输入指纹、成功或业务失败回执与状态一起原子替换到磁盘。写入失败不安装内存状态；IPC 回执丢失时，客户端用同一 ID 重试一次，不重新扣费或扣物品。
- 状态带递增 `revision`；客户端串行提交并拒绝旧投影，未提交的位置和设置不会把养成快照写回覆盖。IPC 只接受桌宠主 frame 的请求。

## 契约与存储边界

命令类型在 `src/shared/pet-command.ts`，注册与运行时输入验证在 `src/core/pet/commands.ts`。即时调用返回 `succeeded + data` 或 `failed + code/message`，连同当前快照和是否重复请求。没有开放 MCP、HTTP、CLI 或外部 Agent 可写端口。

请求包含当前存档的 `epoch` 和 `毫秒时间:UUID` 形式的 ID。同一个 ID 的参数改变会返回 `REQUEST_CONFLICT`；导入或重生会更换 epoch，旧调用返回 `STALE_PET`。请求时间不允许超过宿主时间一分钟。

当前游戏命令使用 24 小时去重窗口，最多保留 1,024 条回执。过期 ID 始终返回 `REQUEST_EXPIRED`，不会因回执清理而重新执行；窗口满时明确返回 `REQUEST_LIMIT`，不提前删除有效回执。这个上限只约束显式游戏命令，时钟和绝对偏好更新不积累回执。后续长任务的检查点和永久执行事实需要独立数据库，不能套用该短期游戏回执策略。

兼容存档仍为 `save.json`。内部 `_agentPetRuntime` 保存 epoch、revision 和有限回执，与宠物修改共用一次临时文件写入、flush 和原子替换。启动校验内部记录，记录损坏时停止加载并保留文件。渲染快照和普通导出不包含这个内部记录；导出仍清空 API Key，旧扩展数据继续保留。这里没有把聊天、任务或长期记忆放入宠物存档。

本批未增加运行依赖。同步文件提交、完整进程组资源占用和长期运行仍需按性能文档实测；本批功能回归不是性能验收。
